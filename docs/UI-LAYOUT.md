# 工作台布局决定

保持原生 ES 模块、现有 CSP 和离线测试。参考本轮[布局研究](FRONTEND-RESEARCH.md#9-第二轮布局调研2026-11-04)：采用项目分组、可见的等待状态、底部输入框、折叠工具记录、独立改动面板；只参考布局，不复制代码。

| 频率与任务 | 位置与操作步数 |
|---|---|
| 一直：团队工作还是等我、等什么 | 顶部状态和单行问题摘要直接显示，左侧会话行同样标记，0步；无法判断等待对象时明确说等待对象未确认 |
| 一直：给负责人回话 | 底部常驻输入框，输入后发送1步；按会话保存草稿到 sessionStorage，切换和刷新均保留 |
| 一直：读负责人回复 | 中央独立气泡，团队活动默认折叠，0步 |
| 经常：成员工作、阻塞和失败 | 右栏上半部常驻卡片，0步；窄屏点团队面板1步 |
| 经常：暂停、继续、中断、重试 | 输入框上方暂停/继续、工作中打断1步；停止收进更多并二次确认；成员卡工作中打断或失败重试1步 |
| 经常：项目和会话切换、看谁等我 | 左侧按项目列会话和状态，切换1步；手机宽度点项目按钮再选择2步 |
| 经常：文件与差异 | 顶部改动按钮1步，列每个工作目录文件，点击文件1步展开实际差异；含暂存、未暂存、未跟踪文件 |
| 有时：完整记录与工具 | 成员卡展开完整记录1步，工具摘要展开1步；最近200条，手动加载更早记录 |
| 有时：白板、私信 | 右下辅助页签1步，成员卡保持可见；白板渲染Markdown |
| 有时：用量、5小时额度 | 成员卡显示轮次和Token；左下额度摘要0步，展开1步看窗口明细；上下文用量单独标明 |
| 偶尔：新会话、选目录、配团队、Git | 左上添加项目1步（浏览器输入路径），项目下新会话1步；弹窗选择Harness、模型、强度、角色，初始化Git沿用明确确认流程 |
| 偶尔：项目规则和笔记 | 右下项目页签1步，规则编辑保存1步，笔记只读展开1步 |

右栏在951px及以上常驻（951–1200px使用300px紧凑宽度），辅助页签不替换成员卡；更窄窗口使用覆盖式抽屉，留出底部输入区，并有关闭按钮。小屏左栏可开关，中间最小宽度不再挤出视口。亮暗色跟随系统，不加框架或动画。

等待语义：负责人输出结束且有尚未回答的发言、没有待队友回复或正在工作成员时，提示“等你回复”；若团队仍在工作，负责人仅进入wait则提示“负责人等待消息，团队仍在工作”，不伪造权限请求。问题语句明确时即使Worker仍运行也突出“等你回答（根据负责人发言）”。最后发言直接展示，点击回答聚焦输入框。会话列表由服务端增量摘要提供，未选中会话也能显示提醒。

旧日志的连续无ID文本只在相同成员、相同轮且无用户输入或完成边界时合并；有messageId严格按ID合并。初次载入的错误保持折叠；只有成员停摆或会话出错才自动展开，工具失败保持折叠并在摘要显示数量。内部事件不会形成“0步”活动。渲染保持250ms合并、稳定DOM与上翻位置、最近200条初始窗口。改动、项目文件与白板仅按需读取，避免每250ms执行Git。

与初步建议的差异：成员卡和辅助面板拆开，避免切白板后丢失成员状态；增加顶部改动直达入口，小屏左右栏均可收起。附件、行内评论、任意面板拖拽不属于本任务必需功能，不引入。没有真实用户审批事件时不展示虚构审批按钮。

## 离线预览与验收

先 `D:/Node/npm.cmd run build`，再 `node scripts/ui-preview.mjs --url-file .test-state/preview-url.txt`。脚本只启动自己的假服务，不扫描模型、不启动真实Harness；地址只写文件。浏览器打开该文件中的地址，点击左侧示例会话。按 Ctrl+C 关闭自己启动的服务，预览数据留在仓库 `.test-state/ui-preview-*` 以便检查。

建议在宽屏与390px窄屏分别检查顶部问题、回答聚焦、项目切换与草稿、抽屉开关、长对话上翻、旧错误折叠、新失败提示、成员重试、Markdown白板、私信、差异和规则。窗口隐藏到托盘与托盘退出需要沙箱外Electron验收；后续壳退出联动已改为跟随服务身份/存活状态，仍需沙箱外验收。等待对象根据事件与负责人发言推断，界面会明确显示这种依据；缺少真实Token累计时保留未计量，上下文占用单独显示。

## 审查处理与边界

Qwen独立检查了第4节任务表及预览接口。已修复普通终端预览的父Git仓库继承、额度展开态和提示覆盖、暂停问题卡消失、失败状态被暂停覆盖、无关协作事件触发Git刷新、角色无法选择等问题；增加相应离线回归。项目区域是常驻section，没有“项目details展开态”，该部分发现不成立。改动面板采用显式刷新，避免团队事件频繁触发Git；等待通知按会话等待状态变化去重。

保留已有全历史读取与内存摘要机制，200条约束是初次DOM渲染窗口，不表示网络与后端历史已分页；超长历史的传输和驻留内存仍随日志增长。浏览器预览只有页内等待提示，系统通知通过桌面壳发送。研究只证明了文档或截图说明中的布局，未实际查看截图画面；未复制外部代码。

## 浏览器验收修正

成员默认显示名字、状态、单行摘要和紧凑操作；重试或打断与名字同行，完整记录为小字折叠入口，Harness、模型、轮次与Token在入口悬停和展开后查看。失败成员排首位，其次为等用户回答的负责人、等待消息成员、其余成员；排序复用已有卡片和展开状态。成员区域按内容分配高度，最多占右栏65%，优先保留恢复入口。

打开或切回会话立即替换标题与唯一选中态，清除旧问题和提醒，显示加载中；加载完成后贴底，顶部问题卡更新与视口高度改变时延续贴底，上翻则保留阅读位置。会话行明确拆成状态点加标题、短状态加相对时间两行，项目路径单行省略并提供完整悬停提示。

本轮离线DOM回归覆盖上述交互及模拟横幅造成的162px高度变化；没有实际浏览器布局引擎，1440×900三卡完整显示、1024×700失败卡及重试可见仍需沙箱外浏览器复验。

## 成员执行与等待状态

成员卡按工具ID保留未完成调用，展示最早工具的命令摘要、事件开始时间计算的分钟数和其余工具数量；完整命令放在悬停提示，无command时显示工具名。Codex同时上报开始和完成事件。回合结束、失败、打断、成员重新启动会清空未完成工具；重启后未加载的历史会话不展示运行中，页面刷新恢复仍在运行的会话则沿用日志时间。

wait_for_messages单独显示等待时长，重复心跳不计活动、不刷新开始时间或会话最后活动时间。等待对象只来自本人发出的未回应请求（reply-pending、ask、reply_requested或有效@提及），收到定向回复或请求清除事件后撤去；缺乏证据时只写“等待消息”。全页仅一个1秒计时器更新既有卡片文字，不请求接口、不重建成员或对话列表。隔离预览覆盖长脚本、多工具、已知/未知等待对象、无命令工具、失败及缺失完成事件的已结束回合。

## 额度、壳和交互细化（2026-11-04）
额度属于服务状态：Codex 主动读取固定为 QUOTA_POLL_MS（5分钟），跨会话和成员共用一个读取任务，不随回合读取，失败只写警告；无可用 Codex 成员或其会话全部暂停时跳过。推送的 Codex/Claude 窗口继续接收，Claude 标明“仅工作时更新”和相对更新时间，Qwen 不显示额度。已知耗尽只在下一轮提交前拦截，真实回合的 usageLimitExceeded/rateLimitExceeded 继续走 quota 暂停路径。
5小时/周窗口剩余严格低于15%时向使用该 Harness 的会话负责人发送平台消息，工作中排队，等待时唤醒。负责人同 Harness 时顶部同时提示用户；负责人已耗尽则不再投递给他。quota-notice/quota-rearmed 写入各会话日志，同窗口同重置周期去重，恢复至15%或新周期重新计数，重启恢复去重状态。
停止会话和移除项目进入“更多”并确认；停止明确不可继续，建议暂停。等待横幅为一行摘要，查看全文打开可关闭弹窗，原问题保留于对话。首条输入合并空白后截取36字作标题，更多中的改名持久化（最多60字）。成员名旁状态点、Harness/模型小标签常见，活动摘要最大；操作在鼠标悬停/键盘聚焦时突出，触屏和窄屏始终可见。对话减框线，用户底色和负责人标签明确区分，长文72ch上限，团队活动为细线。
白板/私信页签显示未读数，明确点击清零；各会话的已读事件序号存于 sessionStorage，切换与刷新保留。现有单定时器只更新已有活动和额度更新时间文字；250ms合并、200条初始窗口和上翻位置保持不变。
桌面壳每秒检查其连接的服务PID和锁身份；服务退出或锁释放/身份改变时销毁窗口、托盘并退出，不执行额外服务关闭。红叉仍隐藏到托盘。离线测试覆盖服务身份判定，实际 Electron 和亮暗色像素布局由验收人在沙箱外冒烟。

## 会话标题

新会话首条消息立即按原逻辑截成36字占位，同时独立生成简短中文标题；左栏和顶部通过现有 `session-renamed` 事件更新，无需刷新。优先使用 Codex 的 `gpt-6-luna`，从模型自身支持列表选择最低推理强度；报错或20秒超时后，仅用本地 Qwen（off）兜底一次。两者失败保留占位，只写服务数据目录的 `title.log`，不显示错误。超时常量为 `TITLE_TIMEOUT_MS`。

标题只发送首条用户消息的前2000字，清除控制字符、换行、外层引号和句号，并限制32字；界面使用 `textContent` 显示。标题调用不依赖团队配置，不进入成员上下文、历史、轮次或 Token 统计。Luna 使用独立临时目录和 ephemeral 线程，禁止工具、项目规则、记忆和持久历史，调用后关闭自己的 app-server；Qwen 直接使用 `localModel` 校验后的回环 Responses 地址，禁用重定向，没有 DeepSeek/云端回退。

首发前持久化生成标记，重启不重试，旧会话不回填。用户指定名称或手动改名优先；改名、停止会话或关闭服务会取消待完成请求，迟到结果丢弃。

离线测试可注入 `startApp({ titleRequest })`，假团队默认不会调用真实标题模型。人工真实验收脚本不在 npm test 中：构建后运行 `node scripts/title-check.mjs --authorized-this-run --both` 各调用 Luna、Qwen 一次；`--authorized-this-run --skip-luna` 只检查本地 Qwen。省略 `--both` 则按正常顺序仅在 Luna 失败时兜底。输出模型、耗时和清洗后的标题；必须在沙箱外由验收人明确授权运行。
